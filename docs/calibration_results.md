# Calibration Results

Generated by `utils/calibration.py`. This is the empirical justification
for the `confidence_bands` values in `kpi_contract.yaml` — these numbers
are derived from the table below, not chosen by feel.

Evaluated on 24 synthetic labeled scenarios (18 real anomalies, 6 noise cases).

| Threshold | Coverage | Precision | # Accepted |
|---|---|---|---|
| 0.85 | 0.17 | 1.0 | 4 |
| 0.75 | 0.29 | 1.0 | 7 |
| 0.7 | 0.33 | 1.0 | 8 |
| 0.6 | 0.42 | 0.9 | 10 |
| 0.5 | 0.54 | 0.85 | 13 |
| 0.45 | 0.67 | 0.81 | 16 |
| 0.35 | 0.79 | 0.84 | 19 |
| 0.25 | 0.88 | 0.81 | 21 |
| 0.15 | 0.96 | 0.78 | 23 |

**Reading this table:** lower thresholds accept more cases (higher
coverage) but let more false positives through (lower precision).
Higher thresholds abstain more often but are more trustworthy when
they do answer.

- **Recommended `high` threshold: 0.7** — the most permissive threshold that still achieves precision >= 0.95 (actual: 1.0, coverage: 0.33).
- **Recommended `medium` threshold: 0.5** — the most permissive threshold that still achieves precision >= 0.85 (actual: 0.85, coverage: 0.54).

Update `confidence_bands` in `kpi_contract.yaml` to match the
recommendations above. Re-run this script any time the scoring
weights in `engine/confidence.py` change — the right threshold
is a property of the scoring function, not a fixed constant.
